## 案ごとの詳細

### A案 index.html — 該当3・部分2

- **❌ 03 均等3カラム＋ふわ影**: `.stats-grid { repeat(3,1fr) }`（714行）に stat-card 4枚（3+1の孤立行）、`.voice-grid { repeat(3,1fr) }`（840行）に voice-card 5枚（3+2）。カードは `--shadow-card: 0 4px 16px rgba(43,43,58,0.07)`（224行）のふわ影＋hoverで `--shadow-float` に昇格（1928行）。クセの典型形。
- **❌ 06 ピルボタン**: `border-radius:999px` が12箇所。ボタンだけでなくタグ・バッジまでカプセル形に統一。
- **❌ 09 中央揃え見出し**: `.sec-title { text-align:center }` が既定（310行）。HTML内の使用は中央13回 vs `.sec-title-left` 1回。「eyebrow＋中央見出し＋一文」の型そのもの。
- **⚠️ 05 glassヘッダー**: `.site-header.is-scrolled` で `rgba(255,255,255,.95)`＋`blur(8px)`（402-405行）、下部sticky CTAも同様（1406-1408行）。スクロール時限定・不透明度95%と控えめだが構造は同じ。
- **⚠️ 07 hover浮き上がり**: `.btn:hover -2px/-3px`（363・1936行）、`.feature-card/.voice-card:hover -4px＋影昇格`（1928行）。-8pxより穏やかだが「カードもボタンも一律に浮く」文法は残存。`@media(hover:hover)` ガードは良い。
- ✅ 良い点: 紫系ゼロ（桜ブランドカラーで統一）、アイコンは実写真、無限ループの装飾アニメなし（heroRise/stampPopは一回きりの入場のみ）、和文フォント7種を用途別にサブセット埋め込み。

### B案 hitotonari.html — 該当4・部分2

- **❌ 03 均等3カラム＋ふわ影**: `.voice-grid { repeat(3,1fr) }`（253行）、`.num-card` に `box-shadow:0 12px 30px rgba(184,50,79,.08)`（150行）、`.req-table` にも浮き影（276行）。
- **❌ 05 glassヘッダー**: `.site-header { rgba(255,255,255,.94); backdrop-filter:blur(10px) }`（77行）— 常時適用の教科書的glassmorphism。4案で唯一の常時ガラス。
- **❌ 06 ピルボタン**: `border-radius:99px` が12箇所。ボタン・ロゴバッジ・チップ・マーカー下線まで全部カプセル。
- **❌ 09 中央揃え見出し**: `.sec-head.center` の使用が8セクション中7（`class="sec-head center"` 7回 vs 素の `sec-head` 1回）。手書き英字ラベル＋中央明朝見出しの型。
- **⚠️ 04 blob的装飾**: ぼかしblobは無いが、`hero-bg-circle`（`border-radius:50%` の淡色円・94/498行）＋花びらが `sway 7s infinite` で漂い（96-104行）＋`spin-badge` が20秒回転（125行）。「時間が来たら勝手に動く装飾」という点で同系。`prefers-reduced-motion` 対応済み（128行）は緩和点。
- **⚠️ 07 hover浮き上がり**: `.btn:hover { -2px＋0 8px 20px rgba(0,0,0,.15) }`（63行）。
- 参考: `.photo-ph` のピンク系グラデ（118行付近）は写真プレースホルダーで、実写差し替え前提とコメントあり。装飾グラデではないが、差し替え漏れがあるとクセ01に見えるので公開前に要確認。

### C案 editorial.html — 該当0・部分2

- **⚠️ 04 浮遊装飾**: 花びら2枚が `drift 19s/24s infinite` で漂う（198-200行）＋CTAの「呼吸」アニメ（438行）。面積極小・低速で軽微だが「時間が来たら勝手に動く装飾」ではある（機械チェッカーによる検出。当初の手動監査では見落とし）。
- **⚠️ 06 ピルボタン**: `--r-pill:999px` を14箇所で使用。ただし角丸を3値（999px/14px/6px）にトークンで制限し（75-77行）、ピルはCTA・タグに限定。コメントで規律が明文化されており「無自覚な既定値」ではない。
- ✅ 影ゼロ・罫線主義を宣言どおり実装（`box-shadow` 実質なし、`nav-list` は `box-shadow:none` 明記）。見出しは `kicker`（左揃え・和欧ラベル＋罫線＋通し番号、156-160行）で中央揃え既定なし。ヘッダーは `rgba(255,255,255,.94)` だが **blurなし**。hover浮き上がりなし（`data-reveal` は入場アニメのみ)。
- 参考: スクロール進捗バーが桜→深桜のグラデ（2px・135行付近）だが、紫系でなく面積も極小。

### D案 gravure.html — 該当0・部分1

- **⚠️ 06 ピルボタン**: `border-radius:999px` が7箇所、CTA系（`.btn`/`.btn-line-mini`/`.hd-cta`）と小タグ中心。
- ✅ ヘッダーは不透明パネル＋1px罫線（209行）でガラスなし。影は下部sticky CTAバー（固定UI）のみでカードに影なし。図版番号（Pl. 01…）＋キャプションの誌面文法で見出し中央揃えなし。hover浮き上がりなし。絵文字ゼロ。

## 共通所見と改善の優先度

出典サイトの結論は「参照先を一つ渡した瞬間にLPの顔は変わる」。この監査でも、**誌面という様式を一つ持っているC案・D案はクセがほぼ消え、テンプレ骨格のA案・B案に構造系のクセが残る**という同じ構図が出た。

A案・B案の「AI感」を抜くなら、効果順に:

1. **見出しの中央揃え既定をやめる（クセ09）**: C案の kicker 文法（左揃え・罫線・通し番号）を移植するのが最小コスト。A案は `.sec-title` の既定を左揃えに反転し、中央は明示クラスに。
2. **均等3カラムカード＋ふわ影を解体（クセ03）**: 影を消して1px罫線区切りに（C案式）、または写真を主役に（D案式）。A案 stats は4枚を3カラムに入れて孤立行が出ており、レイアウト上も要修正。
3. **B案ヘッダーのblur除去（クセ05）**: 不透明度.94なら `blur(10px)` の視覚効果はほぼ無い。`background:#fff` 系＋1px罫線で十分。
4. **ピルの適用範囲を絞る（クセ06）**: LINE緑CTAのピルは日本の採用LP慣習として維持で良い。タグ・チップ・バッジ類は小さめ角丸（C案の `--r-s:6px` 相当）へ。
5. **hover浮き上がりの整理（クセ07）**: 全カード一律の浮き上がりをやめ、リンクであるカードだけに限定するか、下線・背景色変化に置き換え。

なお、コード内コメントが参照している `CLAUDE.md`・`docs/design-note.md` はリポジトリに存在しない（`index.html` 185行ほか）。規約の出典が消えているので、復元するか参照を削除しておくと安全。

## 改修の前後で品質変化を確認する方法

`tools/` に検証ツールを用意した（使い方は [tools/README.md](../tools/README.md)）。

1. **数字で見る**: `python3 tools/check-ai-tells.py` — 本監査の10項目をヒューリスティック判定し、ページごとのスコア（低いほど良い）を出す。改修の前後で実行して差を見る。
2. **目で見る**: `node tools/capture.mjs before` → 改修 → `node tools/capture.mjs after` — 375/1280pxのフルページスクリーンショットを `docs/shots/` に保存し、前後を並べて見比べる。
3. **手で確かめる**: hover・タップの手応え・イージング・スクロール時のヘッダー挙動は静止画に写らないので、実機（スマホ）で該当箇所を触って確認する。
4. **原則**: 出典サイトの検証方法と同じく、**一度に1つだけ変えて**前後を比べる。複数まとめて変えると、どの変更が効いたのか切り分けられなくなる。
